# PR のグラレコ図解(/grareco)

目的: PR の設計変更を「AS-IS → TO-BE + 持ち帰り付箋」の 1 枚ボードに圧縮する。
図は鑑賞用ではなく**試験素材** — 付箋がそのまま /tutor の確認質問になるように作る。

## 手順

1. **対象の特定**
   - PR 番号 → `gh pr view <番号>`(本文)+ `gh pr diff <番号>`(差分)
   - 引数なし → カレントブランチと master の diff
   - PR 本文の「設計判断」「危険箇所 top3」を必ず読み込む(付箋の材料はここにある)

2. **物語の抽出**(コードの羅列ではなく「変化の意味」を描く)
   - **セクション①**: 代表的な 1 操作の旅路(read 1 回、cd 1 回、fork 1 回など)を
     AS-IS / TO-BE のフロー図で対比する。ステップは 4〜6 個まで
   - **セクション②**: データ構造・所有権の変化をカード図で対比する
     (構造体のフィールド増減、状態の引っ越し先、共有関係など)
   - **付箋 3 枚**: この PR が守る/意図的に受け入れた invariant・トレードオフ。
     「バグ」ではなく「設計判断」を優先し、必ず**「壊れると何が起きるか」**まで書く

3. **HTML 作成**
   - このディレクトリの `template.html` をスクラッチパッドに `pr<番号>-grareco.html` として
     コピーし、`<!-- EDIT: -->` コメントの箇所だけ差し替える
   - デザイントークン(色・フォント・手書き風スタイル)は変更しない(全 PR で統一された
     視覚言語を保つため)

4. **Artifact で公開**(チャット直貼りや mermaid は不可 — ターミナルでは描画されない)
   - 新しい PR = 新しいファイル名 + **新しい favicon 絵文字**(1 PR = 1 アーティファクト)
   - 同じ図の修正 = **同じファイルパス**で再 publish(URL 維持・favicon 変更禁止)

5. **報告**: URL + 3 段構成の要約(各 1〜2 行)+ 「付箋 = /tutor で確認したい論点」を明記

## 視覚言語(全 PR で統一)

| 要素 | 意味 |
|------|------|
| 赤枠パネル・赤吹き出し | AS-IS / 問題 / 危険 |
| 青緑枠パネル・青緑吹き出し | TO-BE / 解決 |
| 中央の手描き矢印(bridge) | 「この PR で」の変化点。ラベルは 2 行以内 |
| 黄色マーカー(`<mark>`) | 各パネル最重要の 1 フレーズだけ |
| 黄色付箋(sticky ×3) | 持ち帰り invariant(= /tutor の論点) |
| 打ち消し線(`.dead` / `.gone`) | この PR で削除されたもの |
| カード(`.fdcard` / `.ledger`) | 構造体・台帳・テーブルの中身 |

- 手書き風フォント: UD デジタル教科書体 → Klee One → Segoe Print のフォールバック(Windows 想定)
- ライト / ダーク両テーマ対応(`:root` トークン + `data-theme` 上書き。崩さないこと)
- 外部リソース参照は一切不可(Artifact の CSP)。CSS/JS/フォントはすべてインライン

## 注意

- 変更が小さい PR(±100 行未満の機械的変更)はグラレコにしない。断って文章要約にする
- 数値(diff 行数・ファイル数・PR 番号・日付)はフッターに正確に入れる
- 付箋の内容は PR 本文の「危険箇所 top3」と矛盾させない(同じ話を同じ言葉で)
